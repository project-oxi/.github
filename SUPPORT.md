# Getting Support — project-oxi

The project-oxi community communicates primarily through GitHub. There is no Discord, Slack, or IRC channel.

## How to get help

| Need | Where |
|------|-------|
| **Bug report** | Open an Issue on the affected repository (e.g. `oxicode`, `oxios`, `oxinot`) |
| **Feature request** | Open an Issue with the `enhancement` label |
| **How do I…?** | Open a Discussion in the affected repository's **Q&A** category |
| **Security vulnerability** | Email **security@a7garden.dev** — do NOT file a public issue |
| **Code of Conduct violation** | Email **security@a7garden.dev** |
| **Design system questions** | See [`DESIGN.md`](./DESIGN.md); open a Discussion if not covered |

## Before opening an issue

1. **Search existing issues** on the target repository. The same question is often answered already.
2. **Check the docs** — every repo has a `doc/` directory with numbered sections (Korean or English).
3. **Update to the latest release** — your bug may already be fixed.

## What to include in a bug report

- **Reproduction steps** — minimal code/commands to trigger the bug
- **Expected vs actual behavior**
- **Environment** — OS, Rust version (`rustc --version`), commit SHA or release tag
- **Logs / error output** — paste the full error, not a screenshot

## Response time

The project is maintained by a single team on a best-effort basis. We aim to:

- Acknowledge new issues within **7 days**
- Triage and label within **14 days**

There is no guaranteed resolution timeline. Critical bugs and security issues are prioritized.

## Commercial / consulting support

For commercial support, custom development, or consulting engagements, email **security@a7garden.dev** with the subject line starting with `[Commercial]`.

## Language

- **Code, comments, commit messages, PR descriptions** — English
- **UI strings** — Korean is welcome in oxipage, oxinot, oxiline, oxios (where the audience is bilingual)
- **Issue / discussion body** — either English or Korean is fine
